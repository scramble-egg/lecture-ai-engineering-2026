# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：
AIE2026を「AIエンジニア育成プログラム2026年など」と推測し、一般的な3段階として「レベル1：基礎」「レベル2：応用」「レベル3：発展・挑戦」を説明した。また、正確な定義は講座の資料や講師に確認するよう勧めた。

- 用語集の正しい意味と比べて気づいたこと：
用語集では「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」の3段階で、どれか1つに取り組めば完了、原則として採点しない。モデルの答えは「基礎」「発展」の名前だけ偶然合っていたが、2つ目を「応用」と答え、「レベル1・2は必須」は「どれか1つで完了」というAIが言う一般論とはずれていた。

- 表示できたトークン数（入力 / 出力）：
入力：２１、出力：４２４


## 宿題

- 取り組んだレベル：発展

- やったこと：
ask.pyを編集し、応答時間を表示させるコードを実装。演習で用いた、「LoRAとは何ですか？」と「AIE2026の講座の宿題にある「3レベル」とは何ですか？」の２つの質問をgemini-3.5-flash-liteとgemini-3.5-flashの2つのモデルで３回ずつ実行して、応答時間とトークン数を記録した。
flash がなぜ遅いのか気になったので、usage_metadataを全部表示して、思考トークン（thoughts_token_count）を確認。


- 結果：
平均の応答時間は、flash-lite が LoRA 3.36秒・3レベル 2.71秒、flash が LoRA 18.04秒・3レベル 15.22秒だった。どちらの質問でも、flashはflash-liteの約5倍遅かった。
しかし、出力トークンの差は小さく、flashのほうが1.2〜1.3倍多いだけだった。入力トークンはモデルに関係なく同じだった。
flash-liteは2.29〜3.41秒で安定していて、出力が多いほど時間がかかる傾向。flashは11.29〜29.30秒とばらつきが大きく、出力の長さとの関係も見えなかった。
usage_metadataを見ると、flashは回答の前に思考トークンを1000ほど使用。
flash-liteは思考なし（None）だった。
思考も含めると、flash が1回で生成していたのは約1800トークンで、flash-liteの3倍ほどとなる。flash-lite と同じ速さで生成したとしても10秒前後かかる計算なので、flash の応答時間（の大部分は思考によるものだと思う。残りの差やばらつきは、回ごとの思考量の違いやサーバーの混み具合が原因だと考えている。

無料枠のレート制限との関係：
上限は RPM（1分あたりのリクエスト数）、TPM（1分あたりの入力トークン数）、RPD（1日あたりのリクエスト数）の3つで、どれか1つでも超えると429になる。上限は API キーごとではなく、プロジェクトごとにかかる。 
   

- 気づき・疑問：
思考トークンが遅さの一番の原因だったのは意外だった。表示している数字が何を数えているのかを確かめる重要性がわかった。
flashの思考を減らしたり止めたりする設定はあるとしたら、止めてflash-liteくらい速くなるのか、回答の質はどう変わるのかを試してみたい。
また、今回は思考トークンを時間の計測とは別に見ただけだったが、計測のたびに思考トークンも記録すれば、思考量と応答時間の関係を直接確かめられそう。
